  <name>Task 1: Replace _KNOWN_PARAMS with _PARAM_DEFS registry and rewrite set_param/get_param</name>
  <files>cbqs/Model.pyx</files>
  <action>
  Replace the module-level `_KNOWN_PARAMS` set (lines 75-84) with a `_PARAM_DEFS` dict-of-dicts registry. Then derive `_KNOWN_PARAMS = set(_PARAM_DEFS.keys())` from it for backward compatibility with any internal checks.

  **_PARAM_DEFS structure:**

  Each entry maps a param name to a dict with keys: `default`, `coerce`, `validate`, `validate_msg` (optional).

  **Former solve() params to add (new in Phase 15):**
  - `M`: default=-1, coerce=int, no validation (sentinel -1 is valid)
  - `stopping_time`: default=300, coerce=int, validate v > 0
  - `stop_val`: default=-1, coerce=int, no validation (sentinel -1 is valid)
  - `callback`: default=None, coerce=None (skip coercion), validate `v is None or callable(v)`
  - `max_delta`: default=7, coerce=int, validate v >= 0
  - `reset_delta`: default=True, coerce=_coerce_bool (see below), no validation
  - `depth_look_ahead`: default=0, coerce=int, validate v >= 0
  - `num_workers`: default=12, coerce=int, validate v >= 1
  - `results`: default='min', coerce=str, validate `v in ('min', 'average')`
  - `bfs`: default=False, coerce=_coerce_bool, no validation
  - `ignore_constraint_search`: default=False, coerce=_coerce_bool, no validation
  - `monte_carlo_estimate`: default=False, coerce=_coerce_bool, no validation
  - `verify`: default=False, coerce=_coerce_bool, no validation
  - `track_history`: default=True, coerce=_coerce_bool, no validation

  **Existing branching params (keep from Phase 14, now with proper defs):**
  - `branching_bias`: default=None, coerce=float, no validation
  - `branching_weights`: default=None, coerce=None (special validation, keep existing numpy logic), validate='special'
  - `branching_factor`: default=None, coerce=float, validate v >= 0
  - `bias_factor`: default=None, coerce=float, validate v >= 0
  - `look_ahead_factor`: default=None, coerce=float, validate v >= 0
  - `timeout`: default=None, coerce=int, validate v > 0

  **Add a _coerce_bool helper function** at module level:
  ```python
  def _coerce_bool(value):
      if isinstance(value, bool):
          return value
      if isinstance(value, int):
          return bool(value)
      raise ValueError(f"Cannot coerce {type(value).__name__} to bool")
  ```

  **Rewrite set_param():**
  1. Check `name not in _KNOWN_PARAMS` -> raise ValueError (same as before)
  2. If value is None -> `self._params.pop(name, None)` and return (reset to default)
  3. Look up the param def: `pdef = _PARAM_DEFS[name]`
  4. Special case for `branching_weights` -- keep existing numpy validation logic
  5. For all other params: if `pdef['coerce']` is not None, try `value = pdef['coerce'](value)` wrapped in try/except (ValueError/TypeError -> raise ValueError with message)
  6. If `pdef['validate']` is not None and not the string 'special', call the validator: if `not pdef['validate'](value)` -> raise ValueError with `pdef.get('validate_msg', f"Invalid value for {name}: {value}")`
  7. Store: `self._params[name] = value`
  8. For branching params (branching_weights, branching_factor, bias_factor, look_ahead_factor), keep the existing propagation calls that may follow `self._params[name] = value`

  **Rewrite get_param():**
  1. Check `name not in _KNOWN_PARAMS` -> raise ValueError (same as before)
  2. If name is in `self._params`, return `self._params[name]`
  3. Otherwise return `_PARAM_DEFS[name]['default']`

  **Add _get_effective() helper method** on Model class:
  ```python
  def _get_effective(self, str name):
      val = self._params.get(name)
      if val is not None:
          return val
      return _PARAM_DEFS[name]['default']
  ```
  Note: This works for Phase 15 params because none of the solve() params use None as a meaningful stored value (callback=None means "no callback" and is also the default). The branching params with None defaults will return None correctly.

  **IMPORTANT:** Do NOT change the solve() method signature yet. It keeps its current kwargs. This plan only adds infrastructure. Plan 15-02 will strip solve() kwargs.

  **IMPORTANT — Disambiguating `bias_factor`:**
  There are TWO different concepts historically called `bias_factor`:
  1. **Phase 14 branching `bias_factor`** — weight for assignment bias in the 3-term BranchingFunction formula. This IS in `_PARAM_DEFS` (lines 93-94 above) and is an ACTIVE, valid parameter. It stays.
  2. **Old model_t `bias_factor`** — a legacy field on the C model_t struct. This is the one referenced in CONTEXT.md as "silently removed" alongside `manual_bias`. It has no entry in `_PARAM_DEFS` because it was already superseded by `branching_weights` in Phase 14.

  Since the Phase 14 branching `bias_factor` is present in `_PARAM_DEFS`, `set_param('bias_factor', ...)` is a VALID call and will NOT raise ValueError.

  **IMPORTANT:** The `bias` and `manual_bias` params are NOT added to _PARAM_DEFS. They are removed. Setting them will raise ValueError as unknown params per the locked decision.

  **IMPORTANT:** Preserve the existing branching_weights special validation (numpy array checks). Do not replace it with a simple validator -- it needs the numpy-specific checks (1D, length matches self.n, non-negative, no NaN/Inf).
  </action>
