<task type="auto">
  <name>Task 2: Fix inverted realloc condition in preprocessing functions</name>
  <files>cbqs/src/constraint.c</files>
  <action>
Fix ALL instances of the inverted bitmask condition in preprocessing() and preprocessing_sparse().

The bug: `if (counter & (size_steps - 1))` triggers reallocation when NOT a multiple of size_steps (true for ~16383 out of 16384 values). Should trigger when counter IS a multiple.

Search pattern to find all occurrences: `& (size_steps - 1)` with subsequent realloc

Fix each occurrence by changing:
```c
if (counter_X & (size_steps - 1))
    array = realloc(array, ...);
```
to:
```c
if ((counter_X & (size_steps - 1)) == 0 && counter_X > 0)
    array = realloc(array, ...);
```

Locations to fix in preprocessing() (~lines 185-193):
- Line 185: `counter_negative & (size_steps - 1)` for negative_indices
- Line 192: `counter_positive & (size_steps - 1)` for positive_indices

Locations to fix in preprocessing_sparse() (~lines 300-337):
- Line 300: `counter_negative & (size_steps - 1)` for negative_indices
- Line 307: `counter_positive & (size_steps - 1)` for positive_indices
- Line 318: `con->nnz_neg & (size_steps - 1)` for neg_cols, neg_rows, num_negative_indices, negative_offsets
- Line 332: `con->nnz_pos & (size_steps - 1)` for pos_cols, pos_rows, num_positive_indices, positive_offsets

For the nnz_neg and nnz_pos conditions, add `&& counter > 0` check to prevent realloc on first iteration.
