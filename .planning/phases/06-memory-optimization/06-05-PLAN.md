   ```c
   typedef struct {
       dyn_expression_t *dyn;  // Dynamic expression storage
       // Legacy fields for backward compatibility during migration
       int64_t *literals;      // Points to dyn_expr_literals(dyn)
       int *len_literal;       // Points to dyn_expr_len_literal(dyn)
       size_t expr_size;       // Mirrors dyn->expr_size
       int sense;              // Mirrors dyn->sense
       int64_t rhs;            // Mirrors dyn->rhs
   } expression_t;
   ```

4. Keep all function declarations unchanged (add_constant, add_variable, etc.)

This approach:
- Maintains backward compatibility for code accessing expr->literals directly
- Uses dyn_expression_t for actual storage and growth logic
- Allows gradual migration of consumers

<task type="auto">
  <name>Task 2: Migrate Expression.c to delegate to dyn_expr API</name>
  <files>cbqs/src/Expression.c, tests/CMakeLists.txt</files>
  <action>
Rewrite Expression.c functions to use dyn_expr internally:

1. **init_expression()**:
   - Allocate expression_t wrapper
   - Call dyn_expr_init() for the internal dyn field
   - Set legacy pointer fields to point at dyn storage:
     ```c
     expr->literals = dyn_expr_literals(expr->dyn);
     expr->len_literal = dyn_expr_len_literal(expr->dyn);
     expr->expr_size = 0;
     ```
   - Remove fixed MAXCLAUSESIZE * min_size malloc

2. **free_expression()**:
   - Call dyn_expr_free(expr->dyn)
   - Free the wrapper struct
   - Remove separate literals/len_literal free

3. **add_constant()**:
   - Call dyn_expr_add_constant(expr->dyn, constant)
   - Update legacy pointers after (they may have changed):
     ```c
     expr->literals = dyn_expr_literals(expr->dyn);
     expr->len_literal = dyn_expr_len_literal(expr->dyn);
     expr->expr_size = expr->dyn->expr_size;
     ```

4. **add_variable()**:
   - Call dyn_expr_add_variable(expr->dyn, index)
   - Update legacy pointers after

5. **add_expression()**:
   - Loop through expr2's terms and call dyn_expr_add_term for each
   - Update legacy pointers after

6. **sub_constant()**, **sub_variable()**, **sub_expression()**:
   - Similar pattern: use dyn_expr_add_term with negated coefficient
   - Update legacy pointers after

7. **multiply_constant()**:
   - Access literals via dyn_expr_literals, modify in place
   - No pointer update needed (no growth)

8. **multiply_variable()**:
   - Access literals and len_literal, modify in place
   - Check if term length exceeds MAX_VARS_PER_TERM (4), handle gracefully

9. **multiply_expressions()**:
   - Uses init_expression, add_expression internally - already migrated

10. **copy_expression_contents()**:
    - Call dyn_expr_copy(dest->dyn, src->dyn)
    - Update dest legacy pointers
    - Copy sense and rhs

11. **Helper functions** (len_literal, expr_index, compare_tuples, sort_expression, merge_expression, print_expression):
    - These use expr->literals directly which now points to dyn storage
    - Should work unchanged but verify with tests

12. **Update tests/CMakeLists.txt**:
    - Add dyn_expr.c to test_expression target:
      ```cmake
      add_cmocka_test(test_expression
          test_expression.c
          ${CBQS_SRC_DIR}/Expression.c
          ${CBQS_SRC_DIR}/dyn_expr.c
      )
      ```
    - Update all other targets that link Expression.c to also include dyn_expr.c

13. **Remove global min_size**:
    - The dyn_expr module handles growth internally
    - If min_size is used elsewhere for chunked allocation, keep it but don't use for literals

Critical: After each add operation, update legacy pointers because dyn_expr may have reallocated.
