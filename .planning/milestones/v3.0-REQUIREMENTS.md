**Archived:** 2026-03-03
**Status:** All requirements complete

## v3.0 Requirements

### Feature Extraction

- [x] **FEAT-01**: User can extract per-variable feature matrix (n_vars x n_features) from a closed Model — **Complete (Phase 25)**
- [x] **FEAT-02**: User can extract instance-level feature vector (constraint density, variable count, coefficient statistics) — **Complete (Phase 25)**
- [x] **FEAT-03**: Feature extraction works on models of any size without coupling to a fixed dimension — **Complete (Phase 25)**

### Offline Training

- [x] **TRAIN-01**: User can train a weight predictor from a collection of (Model, best_weights) pairs via fit() — **Complete (Phase 26)**
- [x] **TRAIN-02**: User can predict branching weights for a new Model via predict(), returning a numpy array compatible with set_param() — **Complete (Phase 26)**
- [x] **TRAIN-03**: User can save and load a trained predictor via joblib serialization — **Complete (Phase 26)**
- [x] **TRAIN-04**: User can collect training data automatically via a utility that runs short solves with diverse weight strategies — **Complete (Phase 26)**
- [x] **TRAIN-05**: Training pipeline includes uniform-weights baseline in evaluation — **Complete (Phase 26)**

### Online Adaptation

- [x] **ADAPT-01**: User can run an adaptive multi-round solve where weights update between rounds via EMA — **Complete (Phase 27)**
- [x] **ADAPT-02**: Adaptation uses a combined reward signal (objective improvement rate + constraint satisfaction rate) — **Complete (Phase 27)**
- [x] **ADAPT-03**: Online adaptation preserves solver determinism (same seed + threads = same result) — **Complete (Phase 27)**
- [x] **ADAPT-04**: Online adaptation preserves thread safety (no shared mutable weight arrays between workers) — **Complete (Phase 27)**

### Transfer & Diagnostics

- [x] **DIAG-01**: User can train on small instances and apply learned weights to larger instances of the same problem type — **Complete (Phase 28)**
- [x] **DIAG-02**: User can evaluate learned weights against uniform and default baselines via evaluate_weights utility — **Complete (Phase 28)**
- [x] **DIAG-03**: Evaluation reports objective improvement and convergence speed relative to baselines — **Complete (Phase 28)**

### Integration

- [x] **INTG-01**: sklearn is an optional dependency installed via `pip install cbqs[ml]` — **Complete (Phase 25)**
- [x] **INTG-02**: Importing cbqs without sklearn installed does not raise errors — **Complete (Phase 25)**
- [x] **INTG-03**: ML module has clear import error message when sklearn is missing — **Complete (Phase 25)**

## Out of Scope (Validated at milestone completion)

| Feature | Reason | Still Valid? |
|---------|--------|-------------|
| PyTorch / TensorFlow dependency | Overkill for 10-20 features; sklearn sufficient | Yes |
| GNN-based prediction | Requires thousands of training instances; deferred to v3.1+ | Yes |
| Intra-solve C-level weight mutation | Thread-safety risk; inter-solve approach achieves same goal | Yes |
| Algorithm portfolio / multi-solver | Separate milestone scope | Yes |
| GPU acceleration | Not relevant for tabular regression | Yes |
| PassiveAggressiveRegressor | Deprecated in sklearn 1.8 | Yes — used SGDRegressor instead |
