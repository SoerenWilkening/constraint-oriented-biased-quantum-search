<objective>
Eliminate C source duplication in setup.py Extension definitions so each .c file is compiled exactly once, modernize the build configuration with a complete pyproject.toml, and add MANIFEST.in for source distribution control.

Purpose: The current setup.py compiles all 15 C sources into every Cython extension that needs C code (Model, SearchLib, state_sampler, state, Constraint). This means each C file is compiled 5 times per build, wasting build time and creating risk of inconsistency. The fix should compile shared C sources once and link them into each extension. Additionally, pyproject.toml needs full [project] metadata and MANIFEST.in is missing entirely.

Output: Deduplicated setup.py, complete pyproject.toml, MANIFEST.in, working editable and standard installs.
</objective>

  <action>
Restructure setup.py to compile shared C sources exactly once using setuptools' `libraries` parameter with `build_clib`.

**Current state:** The `sources` list of 15 C files is passed directly to 5 different Extension definitions, causing each file to be compiled 5 times.

**Target state:** Use a static library approach:

1. Define a `libraries` list using the `libraries` parameter of `setup()`:
```python
lib_cbqs_core = ('cbqs_core', {
    'sources': [
        'cbqs/src/solver.c',
        'cbqs/src/SearchLib.c',
        'cbqs/src/Branching.c',
        'cbqs/src/intarray.c',
        'cbqs/src/Expression.c',
        'cbqs/src/dyn_expr.c',
        'cbqs/src/state.c',
        'cbqs/src/model.c',
        'cbqs/src/local_search.c',
        'cbqs/src/constraint.c',
        'cbqs/src/quantum_search.c',
        'cbqs/src/approximate_state_sampler.c',
        'cbqs/src/solver_ctx.c',
        'cbqs/src/prng.c',
        'cbqs/src/arena.c',
    ],
    'include_dirs': ['cbqs/src'],
    'macros': [],
})
```

2. Update the 5 extensions that currently use `+ sources` to instead use `libraries=['cbqs_core']`:
```python
Extension("cbqs.Model", ["cbqs/Model.pyx"],
          extra_compile_args=compiler_args,
          include_dirs=['cbqs/src'],
          libraries=['cbqs_core']),
```

Similarly for SearchLib, state_sampler, state, Constraint.

3. Expression extension stays separate (only needs Expression.c + dyn_expr.c, not the full library).

4. Add `-Wall -Wextra` to compiler_args per CONTEXT.md decision:
```python
compiler_args = ["-O3", "-flto", "-pthread", "-Wall", "-Wextra"]
```

5. Keep Metal_executor, Constants, StateGenerator unchanged.

**IMPORTANT:** The `libraries` parameter in `setup()` combined with `libraries` in Extension may not work cleanly with Cython's cythonize. If this approach fails during testing, fall back to an alternative:

**Fallback approach** -- If build_clib doesn't link correctly with Cython extensions:
- Keep the sources in each Extension (current approach) but use the `os.path.join` pattern consistently
- This is acceptable if deduplication via static library proves incompatible with setuptools+Cython
- In this fallback, document WHY deduplication wasn't possible (setuptools limitation) in a comment

```python
# At the top of setup.py, after imports:
def _read_version():
    """Read version from cbqs/__init__.py without importing the package."""
    import re
    with open(os.path.join(script_dir, 'cbqs', '__init__.py')) as f:
        match = re.search(r"^__version__\s*=\s*['\"]([^'\"]+)['\"]", f.read(), re.MULTILINE)
    if not match:
        raise RuntimeError("Cannot find __version__ in cbqs/__init__.py")
    return match.group(1)

# In setup() call, replace version="1.0.1" with:
```
